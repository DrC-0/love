# カードに型を与える (Card / MaybeCard)

カードを表す値がすべて `int` で、「カードが必ずある」箇所と「カードが無いかも
しれない」箇所が型で区別できなかった。番兵の `0` が「無し / 不明」を意味するが、
その判定が場所によって `> 0` と `> 1` に分かれていた。

`Card` (1〜8) と `MaybeCard` (無し + 1〜8) を `card_table.hpp` に作り、
`belief_state` のフィールドと関数の引数・戻り値に適用した。

## なぜ型が要ったか (実際に起きた間違い)

`is_openhand_loveletter` は「双方の手札が互いに既知」を判定するのに
`open_e() > 1` と書かれていた。`> 1` は兵士の判定 (`is_terminated_win`) で
「確定していて、かつカード1でない」を意味する形で (兵士はカード1を宣言できない)、
開手ラブレターでは意味を持たない。相手の手札がカード1と分かっている局面も
除外してしまっていた。**型があれば書けなかった。**

`MaybeCard` に順序比較を定義していないのはこのため。比べたいときは
`has_value()` で存在を確かめてから `value()` で `Card` にする。

## `MaybeCard` が暴いたもの

### 大臣のルールは番兵 0 を加法単位元として使っていた

```cpp
if(bs.have_s(7) && bs.hand_s[0] + bs.hand_s[1] >= 12)
```

**カード同士の足し算**で、手札が 1 枚のとき `hand_s[1] == 0` が加法単位元として
働くことに暗黙に依存していた (合計が最大 8 で 12 未満だから発火しない)。
正しいが読んで分かるものではない。型を入れて `has_value()` の判定を明示した。
結果は変わらない (回帰ハーネスで確認)。

### `able_actions` の `card` はカードではなかった

型を当てようとして初めて分かったが、`able_actions(bs, card, is_second_player)` の
`card` は**カードではない**。`is_lose` が返す多目的のコードで、
カード 1〜8 のほかに `0` (敗北しない)、`9` (ルール上すでに敗北)、
`15` / `25` (魔術師の使用による敗北、対象が自分 / 相手) を取る。

さらに `is_wiz_choice` の分岐では **0/1 の対象選択フラグ**として使われ、
そこで `other_hand_s(card)` が呼ばれていた。`Card` の値域 1〜8 を破るので、
この 1 箇所だけ `Card` を作らずに元の値を直接書いている。

```cpp
// card==0 なら hand_s[0]、card==1 なら「無し」(生の値 0)
const int other_raw = (card == 0) ? bs.hand_s[0].raw() : 0;
```

`able_actions` の `card` 引数は `int` のまま残した。**カードではないものに
`Card` を当ててはいけない。**

## 適用しなかったもの

- **判定の戻り値。** `is_win` / `is_terminated_win` は `std::pair<int, int>` の
  まま。第 1 要素はカード (1..8) だけでなく `0` と `-1` (終局判定に該当せず) も
  取る **3 状態**で、`MaybeCard` (無し + 1..8) では表せない。
- `trash[8]` と `max_num[8]`。カードではなく枚数。
- `able_actions` の行動コードの符号化。0-origin の添字を桁に埋め込む
  シリアライズ形式で、カードを表す数ではない。

## 性能

`Card` も `MaybeCard` も `int` 1 個を包む `constexpr` のクラスで、
`belief_state` のレイアウトは変わらない。ADR 0003 の手順 (交互実行 5 組の中央値):

| 条件 | 型なし | 型あり | 差 |
|---|---|---|---|
| 446 n=5 | 7.06s | 7.02s | -0.6% |
| 557 n=6 | 0.67s | 0.68s | +1.5% |
| 446 n=6 | 0.74s | 0.78s | +5.4% |

いちばん負荷が大きく信頼できる 446 n=5 で -0.6%。n=6 の 2 件は 0.7 秒台で
百分率のノイズが大きい。いずれも 10% 未満なので**零コストと判断する**。

## 不変条件は NDEBUG でも守る

当初は `assert` で守る設計にしたが、**assert は通常ビルド (`-DNDEBUG`) で消えるので
値域は実質まったく検査されていなかった**。しかも `make cfrorgd` は遅すぎて実際には
使われていない。実測すると **16〜17 倍**遅い。

| 条件 | NDEBUG | assert 有効 |
|---|---|---|
| 557 n=7 | 0.07s | 1.22s (17.4 倍) |
| 446 n=6 | 0.75s | 12.23s (16.3 倍) |

遅い原因は `Card` の検査ではなく `loveletter.cpp` の `node::do_action` が毎回呼ぶ
`valid_data()` (`node` の全フィールドを検査する)。比較 2 つの値域検査とは桁が違う。

そこで `assert` をやめ、**NDEBUG に依存しない検査**にした。

```cpp
[[noreturn]] inline void card_range_error(int v, const char* what);

constexpr explicit Card(int v)
  : v_(v) {
  if(v < 1 || v > 8) card_range_error(v, "Card");
}
```

`constexpr` の中から非 `constexpr` 関数を呼んでいるので、**定数式の文脈で値域を
破るとコンパイルエラー**になる。実行時に踏むと NDEBUG の有無に関係なく、
どの値がどの型で範囲外だったかを標準エラーに出して落ちる。

コストは実質ゼロ。ADR 0003 の手順 (交互実行 5 組の中央値):

| 条件 | 検査なし | 検査あり | 差 |
|---|---|---|---|
| 446 n=5 | 6.69s | 6.74s | +0.7% |
| 446 n=6 | 0.72s | 0.73s | +1.4% |
| 557 n=6 | 0.69s | 0.69s | 0.0% |
| 557 n=5 | 5.71s | 5.70s | -0.2% |

**`assert` を使わない理由をここに残す。** このコードベースでは
「assert で守る」は「守っていない」と同義になる。通常ビルドで消えるうえ、
assert を有効にしたビルドは 16 倍遅くて誰も回さないため。型の不変条件のように
**常に成り立っていなければならないもの**は、NDEBUG に依存しない形で書くこと。

なお `win` を手で assert 有効にしてビルドすると `loveletter.cpp:1008` の
`node::valid_data()` で落ちる。**master でも同一箇所で同一に落ちる既存の問題**で、
今回の型付けとは無関係。`node` は `belief_state` とは別の型で今回の対象外。
`cfrorgd` に相当する `wind` ターゲットが無いため、この経路はこれまで一度も
通されていなかった。

## 単体で include できないヘッダ

`card_table.hpp` は `operator<=>` が `std::strong_ordering` を返すのに
`<compare>` を include しておらず、他のヘッダ経由で偶然通っていた。単体で
include すると壊れる状態だったので直した。

同じ問題が `cfr_exp_reward.hpp` にもある (`assert` を使うのに `<cassert>` が
無く、`card_table.hpp` 経由に依存している)。こちらは展開器 8 本の領域なので
今回は触っていない。**誰も単体で include しないヘッダは腐る。**

## 検証

- `make cfr cfr0 cfrorg brrnd brorg win comp cfrorgcnt` が警告ゼロ
- `./regress.sh check full` が **12 項目すべて一致**。今回はロジックを変えないので
  **決定的カウンタも一致しなければならない**という条件で守った。`hand_e` や
  `deck_or_hand_e` の呼び出し回数が 1 回でもずれれば型の当て方を間違えたことになる。
- `make cfrorgd` (assert 有効) で `cfrorg` が完走
