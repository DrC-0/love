# 判定をメモ化する

必勝・必敗の判定は、同じ Belief State を何度も評価し直していた。メモ表を持つ
`belief_state_win_checker` / `belief_state_lose_checker` を導入し、判定 7 本
(`use_win` `enemy_turn_win` `draw_win` `sol_win` `wiz_win` `use_lose` `wiz_lose`)
の結果を覚えるようにした。**壁時計で 4.0〜17.6 倍速**になり、出力は 1 ビットも
変わっていない。

## メモ化が安全である根拠

判定 7 本は `belief_state` と引数以外の可変状態を一切読まない。実測で確認した。

- `end_deck_n` の参照: 0
- `cfr_switch` / `br_switch` / `org_switch` / `br_player` / `table_infset` の参照: 0
- `commentable_bs` の参照: 3 箇所。いずれもデバッグ出力のみ

したがって戻り値は (Belief State, card または to0p) の純関数で、同じ鍵には同じ値を
返す。この純粋性が崩れたらメモ化は壊れるので、**判定からグローバルを読むコードを
足してはいけない**。

## どれくらい重複していたか

先に使い捨てのコードで測った (`archive/measure-memo-feasibility` タグ)。
部分ゲーム 557、打ち切り深さ 6:

| 関数 | 呼び出し | 相異なる状態 | 比 |
|---|---|---|---|
| `enemy_turn_win` | 36,590,596 | 7,742 | 4,726 |
| `sol_win` | 27,616,571 | 4,316 | 6,399 |
| `use_win` | 24,560,516 | 13,975 | 1,757 |
| `draw_win` | 14,846,732 | 2,849 | 5,211 |
| `use_lose` | 1,230,588 | 6,552 | 188 |

**相異なる状態は数千しかない。** しかも深くするほど比が上がる。
`enemy_turn_win` は深さ 8 / 7 / 6 で 1,077 / 1,859 / 4,726 で、呼び出しが
×5.2、×5.5 と指数的に増える一方、相異なる状態は ×3.0、×2.2 と減速する。
表は飽和するが仕事は増えるので、**打ち切りを外した本番ほど効く**。

## 設計

- 鍵は Belief State の 16 フィールドと追加の鍵 (card 0..8 / to0p) を **59bit** に
  詰めたもの。**16 フィールドすべてを含める。** 1 つでも落とすと違う局面が同じ鍵に
  なり、誤った結果を返す。
- **メモ表は関数ごとに分ける。** 同じ (Belief State, extra) でも関数が違えば答えが
  違うので、1 つの表にまとめてはいけない。
- 依存の向きは ADR 0006 のまま。`belief_state_lose_checker` が
  `belief_state_win_checker&` を持つ (`use_lose` / `wiz_lose` が `draw_win` を
  呼ぶため)。逆は無い。
- `is_terminated_win` はメモ化しない。比較数個の安い述語で再帰せず、メモ化後は
  24,566 回まで落ちているので、表を引くほうが高くつく可能性が高い。
  `is_win` / `is_lose` も入口で再帰しないのでメモ化しない。

### checker の寿命が成否を分ける

メモ表は**部分ゲーム 1 回の実行を通して共有されなければならない**。
`cfrorg` は `winlose_visitor` が 1 つだけ作られるのでそこに持たせた。`win` は
`cnt_abs` が情報集合ごとに呼ばれるので、`infset_iswin` で作って参照で渡している。
**`cnt_abs` のローカルにすると呼ばれるたびに表が捨てられ、効果が完全に消える。**

### `commentable_bs` が真のときはメモを迂回する

`commentable_bs` は判定がどのような順で実行されているかを検査するためのフラグで、
`test.cpp` のようなスクラッチから手で `true` にして使う。メモが当たると計算そのものが
飛ぶのでトレースが欠け、**実行順を見るのが目的なのに用を成さなくなる**。そのため
真のときは引きも書き込みもせず毎回計算する。通常は `false` なので分岐予測が当たる。

## 回帰ハーネスの基準を取り直した (2 回目)

この変更では**決定的カウンタが必ず変わる。それが成果そのもの**なので、
12 項目すべて一致にはならない。

| 項目 | 結果 |
|---|---|
| `cfrorg` の stdout 4 項目 | 完全一致 |
| `win` の stdout 2 項目 | 完全一致 |
| `win` の `abs bin` 2 項目 (46MB / 104MB) | sha256 まで完全一致 |
| `cfrorg` のカウンタ 4 項目 | DIFFER (判定が 99.9% 以上減) |

ADR 0006 に書いた「差が意図したものだけであることを機械的に示してから取り直す」に
従い、カウンタの全項目を突き合わせて**増加したものが 1 つも無い**ことを確認した
うえで取り直した。1 回目は ADR 0006 のカウンタ名変更。

## 次のボトルネックが移った

メモ化後に落ちなかったカウンタは 2 つだけで、しかも同じ処理だった。

```
belief_state_from_history   910,276   (メモ化前後で不変)
reset_flag_by_use         2,934,791   (その内訳。belief_state_history.hpp:50,102 から)
```

`visit_winlose.hpp` が意思決定点ごとに履歴文字列から Belief State を組み直す処理で、
メモ化とは無関係に残る。判定が千の桁まで落ちた今、**これが支配的**。
詳細は ADR 0003 の追記を参照。
