渡された実装計画書のとおりに実装します。**計画書が唯一の仕様です。**

## 手順

1. 計画書を読む。
2. 計画書に書かれた変更を、書かれたとおりに適用する。
3. `make cfr cfr0 cfrorg brrnd brorg win` が通ることを確認する（実行までは不要）。
   `make all` は `watch` のリンクエラーで止まるので使わないこと。
4. 変更した行だけを整形する: `git add -p && git clang-format`（clang-format 14 系）。
5. 何をどう変えたかを報告する。

## 止まるべきとき

計画書に書かれていない設計判断が必要になったら、**その場で止めて報告する**こと。
勝手に決めてはいけません。それは実装のバグではなく計画のバグなので、
計画側で埋めてもらう必要があります。

特にこのリポジトリで判断を迫られやすい箇所:

- org（兵士の宣言がプレイヤーの意思決定）と rnd（一様ランダムに抽象化）の
  どちらを触るのか、両方なのかが計画書から一意に決まらないとき
- 行動履歴の末尾を「追記」するのか「payload 付きに置換」するのかが書かれていないとき
- `bf_position` の `_s` / `_e` のどちらの視点の話かが曖昧なとき

## 禁止事項

- 計画書に無い改善・リファクタ・コメント追加・整形パスを勝手にやらないこと。
- テストやドキュメントを頼まれていないのに追加しないこと。
- master に直接コミットしないこと。
